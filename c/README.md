# py - a Python 3 subset interpreter in strict C89

One amalgamated source file (`py_all.c`, generated from `src/*.c` by
`tools/amalg.sh` and checked in). No dependencies beyond the C library and libm.

## Build and run

    make            # cc -std=c89 -pedantic -Wall -Wextra -O2 -DPY_LIBDIR=... -o py py_all.c -lm
    make LIBDIR=/path/to/pylib     # compile-time fallback library dir (default ../pylib, absolute)
    make posix      # same with -DPY_POSIX (isatty prompt detection, clock)
    make test       # runs ../tests/run_tests.sh ./py
    make embed      # ./py_embed: pylib/ compiled into the binary (-DPY_EMBED_LIBS)
    make deck       # deck/py_deck.c: the amalgamation folded to 71 columns (VM/370 deck step)
    make deckcheck deck-test embed-test deck-embed-test strict linecheck   # see PORTING.md
    make bench      # sh bench/run.sh, compares against python3
    ./py file.py args...      # sys.argv = [file.py, args...]
    ./py -c 'print(1+2)'
    ./py                      # REPL on stdin (-i forces prompts)

Uncaught exceptions print a traceback and exit with status 1.

## Portability rules

No `//` comments, no mixed declarations, no `long long`, no stdint.h, no VLAs;
all functions static except `main`; character classes use literal sets
(EBCDIC-safe); POSIX only under `-DPY_POSIX`, and only inside `src/p0_os.c`;
development lines <= 100 columns, generated deck <= 71 columns. No C99 library
functions (`snprintf`, `round`, `isnan`, `strdup`, ...). Details, the VM/370
build steps and the list of remaining ASCII/IEEE assumptions: `PORTING.md`.

## Design notes

- 16-byte tagged `Value`; small ints are `long`, larger ones are bigints.
- Mark-sweep GC with explicit gray stack, run only at safe points (call entry,
  loop iterations). `-DPY_GC_STRESS` collects at every safe point.
- Generators have no separate C stack: each compound statement keeps resumable
  state slots in the generator and the executor re-enters along the saved path.
- Exceptions use setjmp/longjmp; recursion limit 1000 raises RecursionError.
- Sets and frozensets (`frozenset` is its own type, not a subclass of `set`; operators return the
  type of the left operand; the hash is CPython's `_shuffle_bits` scheme) emulate CPython's
  open-addressing table (`setobject.c` of 3.13: linear probes 9, perturb shift 5, dummies, growth
  x4 / x2 above 50000, fill 3/5, `pop` finger, `set_merge`, `set_table_resize`, the constant
  folding of set displays), so the iteration order of sets of ints, bools, None, floats,
  complex numbers, tuples and frozensets of those is the same as in CPython (exact where
  `unsigned long` has 64 bits; `tuple` hashes use CPython's xxHash scheme). Instances of classes
  with a user `__hash__` are called at insert time and ordered by the value returned: a result
  that fits a signed 64-bit `Py_hash_t` is kept (-1 becomes -2), a larger int is reduced like
  `hash(int)` (modulo 2**61-1), a non-int raises `TypeError: __hash__ method should return an
  integer`, as in CPython (`tests/34_hash64.py`, C only: skipped for CREXX via
  `tests/crexx_skip.txt` and for a real 32-bit `long` via `SKIPFILE=tests/m32_skip.txt`). A set
  that receives a key with a per-run hash in CPython (str, bytes, identity-hashed instances)
  switches to insertion order.
- Dicts are insertion-ordered; floats print with the shortest repr that
  round-trips; `sum` uses compensated summation like CPython 3.12.

## Imports

`import x`, `import a.b [as c]`, `from a.b import c, d as e`, `from x import *` (honours
`__all__`, skips `_names`), packages (`__init__.py`), relative imports (`from . import m`,
`from .m import f`, `from .. import n`), `sys.modules` caching, `__name__` (`'__main__'` for the
script), `__file__`, `__path__`, CPython-style circular-import tolerance (a module is in
`sys.modules` before its body runs). Native modules (math random sys time os numpy re json) win
over files. Every module has its own global namespace (globals are name-prefixed `pkg.mod.x`
in one table; builtins live under plain names).

Search path (`sys.path`): directory of the script, the embedded table `<pylib>` (only in a
`-DPY_EMBED_LIBS` build), entries of the `PYLIB` environment variable
(`:` separated), `<dir of executable>/pylib`, `<dir of executable>/../pylib`, then the
compile-time `PY_LIBDIR` (`make LIBDIR=...`, default the absolute `../pylib` of the source tree,
which is where the shared pure-Python libraries live). Only stdio `fopen` is used; path
composition is `host_join` / `host_module_path` in p0_os.c.

`eval`, `exec`, `globals()`, `locals()`, `vars()`, `dir()`, `__import__` are available.

## Language notes (Stage 2)

Multiple inheritance with C3 MRO (`__mro__`, `super()` follows the MRO), `type(name, bases,
dict)`, `__slots__` ignored, `__getattr__`/`__setattr__`/`__new__`, reflected/in-place/comparison
dunders with `NotImplemented`, `__getitem__/__setitem__/__delitem__` with slice objects,
`__iter__/__next__`, `__contains__ __len__ __bool__ __call__ __format__ __enter__/__exit__`,
`property` with setter/deleter, `staticmethod`, `classmethod`, `x = yield`, `send`/`throw`/`close`, `StopIteration.value`, walrus `:=`
(also in comprehensions), the `match` statement (literal, value, capture, wildcard, sequence with
`*rest`, mapping with `**rest`, class, `|` and `as` patterns, guards; `match` and `case` stay ordinary
names elsewhere), positional-only `/` and keyword-only parameters, variable and function
annotations (`__annotations__` of modules, classes and functions; evaluated eagerly), star
expressions in list/tuple/set displays, `ExceptionGroup` / `BaseExceptionGroup` (`split`, `subgroup`,
`derive`, nesting rules) and `except*`, `Ellipsis`, live dict views, function attributes,
nested-quote f-strings and `{x=}`, `print(file=)`, `%` with mapping keys, `dict | dict`.
`io.StringIO` and `warnings` are small pure-Python modules in `../pylib`.

## Known gaps

Strings are bytes (len/index count UTF-8 bytes, case ops ASCII only); sets iterate in
insertion order (their repr differs from CPython for mixed hash orders); `frozenset` is an alias
of `set` (unhashable); no async; `except*` inside a generator is not resumable; `r = yield from g()` (as an
expression) and chained assignment with `yield` are not supported; no generator finalization
on garbage collection; `math.erf/erfc/gamma/lgamma` are within about 1e-15 of libm, not bit-identical
(so `random.binomialvariate` for `n*p >= 10` can differ in the last digit through `lgamma`, and a
float that numpy computes with glibc's FMA-compiled `log1p/expm1/pow` can differ by one ulp).

## Subclassing builtin types and `__new__`

`type.__call__` calls `cls.__new__(cls, ...)` and then `__init__` when the result is an instance of
`cls`; `object.__new__(cls)`, `super().__new__(cls, ...)` and `T.__new__(cls, ...)` work for
`T` in `tuple list dict set str int float bytes bytearray complex` and `Exception`. A subclass
instance carries the native value (`Inst.pay`, built by the base type's constructor) plus an
instance `__dict__`, and the interpreter's own operations honour overrides: `m[-1]` with
`__getitem__`, `len`, `for` (`__iter__`), `in`, `dict.__setitem__(self, k, v)`,
`list.append(self, v)`, `super().append(...)`, `__missing__` (for `d[k]` on a dict subclass),
`==`/`hash`/`+` on str subclasses, `%`/`format`/`int()`/`float()`/`round()` on number
subclasses, and `repr`/`str` as CPython (`S({1})` for set subclasses, plain `repr` of the value
for number/str/tuple subclasses). `collections.namedtuple` classes are real tuple subclasses
(`isinstance(p, tuple)`). Gaps: `frozenset` is still the same class as `set` (mutable, so a
`frozenset` subclass behaves like a `set` subclass); `int`
subclasses of `bool` and `__slots__` are not special; `OSError(2, 'x')` does not turn into
`FileNotFoundError`.

## bytes, bytearray, struct, complex, cmath (src/p7_bytes.c, src/p7_cplx.c)

`bytes`/`bytearray` are native types (`T_BYTES`, `T_BARR`): literals, indexing to int, slices
(also extended and `bytearray` slice assignment/deletion), `+ * in` comparisons, hashing (`bytes`),
`repr` like CPython, iteration, `bytes(n)`, `bytes([..])`, `bytes(str, encoding)`, `str(b, enc)`,
`decode` (utf-8/latin-1/ascii; strict/ignore/replace with CPython's UnicodeDecodeError text),
`hex/fromhex`, `find/index/count/split/rsplit/join/replace/strip/startswith/endswith/partition/
upper/lower/translate/maketrans/zfill/...`, and the `bytearray` mutators (`append extend pop
insert remove clear reverse copy`). `int.to_bytes/from_bytes` (any size, signed). `struct`:
`pack unpack calcsize pack_into unpack_from iter_unpack Struct error` for `x c ? b B h H i I l L q
Q n N f d s p` with `@ = < > !` prefixes (native alignment only for `@`; native sizes assume
LP64 `long`, IEEE floats). No `memoryview`, no `array` module.

`complex` (`T_COMPLEX`, two doubles): literals `3j`, `complex(a, b)`, `complex('1+2j')`, mixed
int/float arithmetic with CPython's algorithms (Smith division, `**` via `cmath`-style polar
form, "complex division by zero"), `abs pow sum ==  hash`, format specs, `repr/str` exactly
like CPython, `.real .imag .conjugate()`. `cmath`: `sqrt exp log log10 sin cos tan asin acos
atan sinh cosh tanh asinh acosh atanh phase polar rect isclose isfinite isnan isinf` and
`pi e tau inf nan infj nanj`. Branch cuts follow cmathmodule.c for finite arguments; the
infinity/NaN special-value tables of C99 Annex G are not reproduced. The libm functions that C89
lacks (`hypot log1p expm1 asinh acosh atanh`) are static replacements in `p7_cplx.c`
(`n_hypot` is correctly rounded to within 1 ulp).

numpy `complex128` (`ND_COMPLEX`, interleaved doubles): inference from complex literals,
`dtype=complex`, arithmetic/broadcasting/comparison (`==`, lexicographic order for `<`), `.real
.imag .conj()`, `np.abs angle sqrt exp log sin cos ... real imag conj iscomplex isreal
iscomplexobj round`, `sum mean prod cumsum cumprod std var min max any all`, indexing, `dot`/`@`,
`polyval`, `np.roots` (real coefficients) and `np.linalg.eigvals/eig`, which return complex
arrays when an eigenvalue is complex (a port of LAPACK dgeev, see numpy.linalg below, so eigenvalue
order and eigenvector normalisation follow numpy). Printing follows numpy's `ComplexFloatingFormat`.
Gaps: `sort argsort unique allclose array_equal count_nonzero diag trace` and `linalg.*` (other
than `eig/eigvals`) raise `TypeError` for complex input; `complex64` is an alias of `complex128`;
the struct half-float format `e` is not supported.

## socket and select (src/p7_sock.c, host adapter in src/p0_os.c)

`import socket`: `socket(AF_INET, SOCK_STREAM)` with `bind listen accept connect connect_ex send
sendall recv recv_into shutdown close settimeout gettimeout setblocking getblocking setsockopt
getsockopt getsockname getpeername fileno detach` and `with`; `create_connection`, `getaddrinfo`
(numeric ports and a few service names), `gethostbyname`, `gethostname`, `getfqdn`,
`inet_aton/ntoa/pton/ntop`, `htons/htonl/ntohs/ntohl`, `setdefaulttimeout`, the usual constants,
`socket.error` (= `OSError`), `socket.timeout` (= `TimeoutError`), `gaierror`, `herror`. Errors
are `OSError` with `errno`/`strerror` (`[Errno 111] Connection refused`) and the CPython
subclasses `ConnectionRefusedError`, `ConnectionResetError`, `BrokenPipeError`,
`BlockingIOError`, `TimeoutError`. A timeout puts the descriptor in non-blocking mode and every
wait is a `select`; `recv`/`send`/`accept` retry on `EINTR`. `select.select(r, w, x, timeout)`
takes sockets, ints or objects with `fileno()` (the exceptional list is always empty).
BSD sockets are compiled only with `-DPY_POSIX`; otherwise `import socket` works but creating a
socket (or resolving a name) raises `OSError: sockets not available`. Gaps: IPv4 TCP only (no
UDP, IPv6, `sendto/recvfrom`, `selectors`, `ssl`); sockets that are not
closed explicitly keep their descriptor until the process ends; `inet_aton` accepts only
dotted quads. `sock.makefile(mode)` (`r`, `w`, `rw`, each with `b`) returns a file object on a
duplicate of the descriptor (closing it leaves the socket open); `socket.socketpair()` returns two
connected `AF_UNIX` stream sockets (`host_sock_pair`, `host_sock_fdopen`).

## os, time and the pure Python overlays (src/p7_imp.c, src/p7_mod.c, pylib/os.py, pylib/time.py)

The native `os` has `getenv getcwd remove unlink rename urandom getpid getppid listdir mkdir rmdir
chdir environ` and `os.path`; the native `time` has `time sleep perf_counter monotonic
process_time` (+ `_ns`) and the C library calendar as `_gmtime _localtime _mktime _tzinfo`. The
overlay mechanism of numpy (`module_overlay`) is generalised: `pylib/os.py` and `pylib/time.py` are
loaded as `os._overlay` / `time._overlay` and complete the native module, so `os.fspath fsencode
fsdecode makedirs walk removedirs replace cpu_count strerror` and `time.struct_time gmtime
localtime mktime strftime strptime asctime ctime timezone altzone daylight tzname` exist
(`hasattr(os, 'listdir')` is true). With `-DPY_POSIX` the time zone follows `TZ` (`localtime`,
`mktime`, `%Z %z`, `tm_zone`, `tm_gmtoff`); without it the host calls fail (`OSError` ENOSYS for the
directory functions, `getpid` is 1) and `pylib/_pytime.py` treats the local zone as UTC.
`random.SystemRandom`, `random.getstate/setstate` and `os.urandom` use `host_urandom`. Open errors
raise `FileNotFoundError`, `FileExistsError`, `PermissionError`, `IsADirectoryError`,
`NotADirectoryError` with `errno`, `strerror` and `filename`.

## Introspection, metaclasses, files (src/p7_rt.c, p5_eval.c, p7_bi.c)

`f.__code__` (`co_name co_qualname co_filename co_firstlineno co_argcount co_posonlyargcount
co_kwonlyargcount co_nlocals co_varnames co_cellvars co_freevars co_flags co_names co_consts`),
`__defaults__`, `__kwdefaults__`, `__annotations__`, `__globals__`, `__closure__`.
`e.__traceback__` is a chain of traceback objects (`tb_frame`, `tb_lineno`, `tb_next`; the frame
has `f_code`, `f_lineno`, `f_globals`, `f_locals` (a snapshot), `f_back`), built on demand from a
compact record taken when the exception is raised; `sys.exc_info()` returns the real traceback;
`sys._getframe(depth)` builds the frame chain with `f_back`. Approximations: `tb_frame.f_lineno` is
the traceback line, frames of a traceback have empty `f_locals`, `except*` and `with` do not attach
tracebacks. `raise X from Y` sets `__cause__`, `__suppress_context__`, and every exception raised in
a handler gets `__context__`. `pylib/traceback.py` (`extract_tb extract_stack walk_tb format_exc
print_exc TracebackException` with cause/context chaining; no `~^~` carets), `pylib/inspect.py`
(`signature`, `Signature`, `Parameter`, `BoundArguments`, `currentframe`, `stack`, `getframeinfo`,
`isgeneratorfunction`), `logging` (`funcName`, `lineno`, `pathname`, `stack_info`) and `types`
(`CodeType FrameType TracebackType GenericAlias`) use them where present and keep their old
fallbacks otherwise (the CREXX port has no frames).

Metaclasses: `class C(metaclass=M)`, `M.__new__/__init__/__call__`, `type(name, bases, ns)`,
metaclass methods and properties found through the class (`len(C)`, `iter(C)`, `x in C`, `C[k]`,
`reversed(C)`), `__init_subclass__` with class keywords and `super().__init_subclass__()`,
`__class_getitem__`, `list[int]`/`dict[k, v]` as `types.GenericAlias`, `Class.__new__(Class)`.
`obj.__dict__` is live (updates, assignment, deletion are mirrored into the attributes). `open()`
supports `r w a x + b t`, binary files read and write `bytes` (`seek tell readinto`), accepts
path-like arguments, and `file.name/mode/closed/buffer`. `str.splitlines(keepends=True)`,
`int(bytes_or_bytearray, base)`.

## re and json (src/p7_re.c, src/p7_json.c)

`re` is a native backtracking engine: tokenizer + parser ported from CPython's `_parser.py`
(same error messages and positions), compiled to a flat instruction array and run by a VM with an
explicit backtrack stack (no C recursion per character; capped at 6M entries, after which
`RuntimeError: regular expression too complex` is raised instead of crashing). Compiled patterns are
cached. API: compile match search fullmatch findall finditer sub subn split escape purge, Pattern and
Match objects, flags I M S X A, `re.error`, classes/escapes, anchors, \b \B, (named/non-capturing)
groups, backrefs, lookahead/lookbehind (fixed width), atomic groups, possessive and lazy quantifiers,
conditionals `(?(1)a|b)`, inline flags, templates (\1 \g<name>) and callable repl.
`json` is native too: dumps (indent sort_keys separators ensure_ascii default allow_nan skipkeys cls),
loads (object_hook object_pairs_hook parse_float/int/constant strict, CPython 3.13 error messages),
dump/load, JSONEncoder/JSONDecoder (overridable `default`), JSONDecodeError.
Differences: strings are UTF-8 bytes, so match offsets, `pos/endpos` and re error positions are byte
offsets (json error positions are in characters); case folding and `\w`/`\s` for non-ASCII are
approximate (ASCII for `\d`); no bytes patterns, `\N{name}`, re.RegexFlag enum or `Scanner` beyond a
minimal one; catastrophic patterns stop at the stack limit with RuntimeError where CPython would keep
going; `endpos < pos` is not emulated. `tests/tools/fuzz_re_json.py` is a differential fuzzer against
CPython (not part of the suite): about 30000 random patterns/inputs and 40000 JSON cases agree.
Speed (bench/run.sh): re_bench native 0.2 s vs pure-Python pylib 19.8 s vs CPython 0.5 s; json_bench
native 0.2 s vs pylib 3.1 s vs CPython 0.16 s.

## numpy subset (src/p7_np.c)

`import numpy as np` gives a native `ndarray` (bool/int64/float64/complex128, up to 8 dims, row-major,
heap type `T_ND`) with broadcasting arithmetic and comparisons, `@`, indexing (ints, slices,
tuples, boolean masks, integer lists) and element/slice assignment, reductions with `axis`,
sort/unique/where/concatenate/stack, `dot`/`matmul` (1-d and 2-d), ufuncs, and numpy's
`print`/`repr` layout (line wrapping at 75 columns, `...` summaries above 1000 elements,
scientific notation rules). Float sums use numpy's pairwise summation, so they match bit
for bit. Gaps: slices, `reshape`, `T` and `b[0]` are copies, not views (`b[0][1] = x` does not
modify `b`); no float32/int32 (the names alias float64/int64; see dtype objects below), N-d `matmul` and multi-array fancy indexing
are unsupported, `a.round()` on reduction results works through a `float.round` method that
is installed on `import numpy`; float matmul does not use BLAS so it can differ in the last
digits from numpy.

### Package behaviour, dtype objects, scalar types

The native `numpy` module has a `__path__` (`<sys.path entry>/numpy` for every entry), so file
submodules in `pylib/numpy/` resolve: `import numpy.fft`, `from numpy.fft import fft`, `from numpy
import fft`, `import scipy.fft`. Native submodules (`linalg`, `random`) are already in
`sys.modules`; the existing overlay (`numpy._overlay`, module_overlay in p7_imp.c) still supplies
missing attributes and is untouched.

`a.dtype` is a `numpy.dtype` instance (one singleton per bool/int64/float64/complex128): `repr`
`dtype('float64')`, `str` `float64`, `.name .kind .char .str .itemsize .type`, `hash`, and `==`
against another dtype, a type (`float int complex bool np.float64 ...`) or a name string
(`'complex128'`, `'f8'`, ...); `np.dtype(x)`, and dtype objects are accepted as `dtype=`.
`np.float64 np.int64 np.complex128 np.bool_` are the builtin `float int complex bool`, so
`np.float64(3.5)` is a plain `float`, and reductions return plain Python numbers
(`type(np.array([1.5]).sum())` is `float`, `type(np.array([1]).sum())` is `int`; numpy gives
`np.float64` / `np.int64`). The abstract classes `np.generic number integer signedinteger
unsignedinteger inexact floating complexfloating` exist; `isinstance`/`issubclass` answer by value
type, so `isinstance(1.5, np.floating)` and `isinstance(1, np.integer)` are True (numpy says False
for Python scalars, True for numpy scalars). Sized names (`int8 uint8 float32 ...`) alias the four
real types.

### numpy.linalg and numpy.random (src/p7_la.c, src/p7_rnd.c)

`numpy.linalg`: `inv det slogdet solve cholesky eigvalsh eigh eigvals eig svd matrix_rank qr
lstsq pinv norm cond matrix_power`, `LinAlgError`. Real double matrices only (2-d, no stacked
matrices). `eigvals`/`eig` return complex arrays when an eigenvalue is complex.

The decompositions are ports of the LAPACK reference algorithms numpy calls, not generic
solvers, so that eigenvalue order and eigenvector/singular vector signs agree with numpy:

| function | LAPACK path ported | notes |
|---|---|---|
| `eigvals`, `eig` | `dgeev`: `dgebal`, `dgehd2`/`dorghr`, `dlahqr`+`dlanv2`, `dtrevc` back-substitution, `dgeev` normalisation | same algorithm as `pylib/numpy/linalg.py` (CREXX) |
| `eigh`, `eigvalsh` | `dsyevd` for n <= 25: `dsytd2`, `dsteqr` (QL/QR), `dormtr` | `UPLO` honoured |
| `svd`, `pinv`, `lstsq`, `matrix_rank`, `cond`, `norm(ord=2)` | `dgesdd` small-matrix path: `dgeqr2`/`dgelq2` when `m >= 11n/6` (or `n >= 11m/6`), `dgebd2`, `dbdsqr` through `dbdsdc`, `dormbr` | `full_matrices` / `compute_uv` supported |
| `qr` | `dgeqr2`/`dorg2r` | `reduced`, `complete`, `r` |

`tests/tools/linalg_diff.py compare ./py N SEED` runs thousands of random matrices (sizes 1..10;
dense, integer, triangular, symmetric, repeated eigenvalues, defective, permutation, companion,
rank deficient, badly scaled, rotation blocks) through both this interpreter and real numpy and
checks values, residuals, orthogonality and, as soft differences, LAPACK order and signs.

Differences that cannot be removed: (1) numpy links an optimised BLAS (FMA kernels, different
summation order), so a QR sweep or reflector that is decided by the last bit can end with a
different sign or phase. About 5% of random dense nonsymmetric matrices give an eigenvector
that differs from numpy by a sign (or a phase, for complex pairs); eigenvalues and residuals
agree. Exactly degenerate cases (repeated eigenvalues of a defective or rank deficient matrix,
the null space of a singular matrix, tied singular values, the vectors beyond the rank in `qr`)
are arbitrary in LAPACK too and are not reproducible. (2) For n > 25 numpy's `eigh` and `svd`
switch to divide and conquer (`dstedc`, `dbdsdc`); this implementation keeps the QL/QR path, so
vectors can differ in sign for large matrices. (3) `eigvalsh`/`svd(compute_uv=False)` use the
same QL/QR iteration as with vectors (numpy uses `dsterf`/`dqds`): values agree to rounding.
(4) `inv`/`solve`/`det` use a left-looking LU in the operation order of OpenBLAS `getf2` (reciprocal
pivot scaling, fused multiply-add dot products, gemv in groups of four columns), so they raise
`LinAlgError: Singular matrix` for an exactly zero pivot exactly where numpy does:
`inv([[1,2,3],[4,5,6],[7,8,9]])` is singular, as in numpy 2.5, while `[[1,2,3],[4,5,6],[7,8,10]]`
and `[[.1,.2,.3],[.4,.5,.6],[.7,.8,.9]]` invert. Checked against numpy 2.5.3 on 3,000 random small
integer matrices (orders 2 to 6): identical verdicts for orders 2 to 5, 7 of 613 differ at order 6
(OpenBLAS kernel details), and the elements of the result agree to the last digits or a few ulp
(`*_diff` tools below). The fused multiply-add is a Dekker emulation in C89 (no `fma()`).
`pylib/numpy/linalg.py` (CREXX) has the same algorithm. Beyond a few dozen rows numpy switches to blocked algorithms and results differ in rounding.
(5) Matrices that are close to singular (condition
number above about 1e10) give `pinv`/`lstsq`/`cond` results that agree only to a few digits.

`numpy.random` reproduces numpy 2.x exactly (checked against numpy 2.5.3: tests/36_random.py and
about 600 further sequences). Legacy: `seed` / `RandomState(seed)` on MT19937 (`init_genrand` for an
int, `init_by_array` for an array), `rand random_sample randint` (masked rejection) `randn` (polar
Box-Muller with its cached value) `shuffle permutation choice` and the distributions `normal uniform
exponential standard_* gamma beta chisquare noncentral_* f standard_t pareto weibull power laplace
gumbel logistic lognormal rayleigh wald vonmises triangular poisson binomial geometric
negative_binomial logseries zipf hypergeometric multinomial dirichlet bytes`, `get_state` / `set_state`. Generator: `default_rng(seed)` is
`SeedSequence` + `PCG64` (128-bit state held as two u64), with ziggurat normals / exponentials, Lemire
bounded integers, `integers(endpoint=)`, `random`, `choice` (Floyd, tail shuffle, `p=`),
`permutation`, `shuffle`, the same distributions, and `PCG64` / `MT19937` / `SeedSequence`
(`generate_state`, `spawn`) objects with `random_raw` and the `state` dict. The six ziggurat tables
cannot be regenerated bit for bit (numpy computes them with its own build-time double arithmetic),
so they are embedded as constants (as is the log-factorial table of the Generator's hypergeometric).
Not provided: `multivariate_normal` and array-valued `n` of `multinomial`; `Generator.integers` with array bounds; 8/16-bit dtypes of `integers` draw
like numpy but are returned as int64; `wald` and the `pareto`/`power`/`rayleigh` family can differ in
the last digit where numpy's build contracts multiply-add or uses glibc's FMA `log1p`/`expm1`.

`random` is CPython's algorithms on CPython's generator (src/p7_pyrand.c): MT19937 seeded by

gammavariate betavariate paretovariate weibullvariate binomialvariate`, `getstate` / `setstate`
(version 3 and 2 states, `gauss_next`), `random.Random(seed)` instances with independent state, a
subclass may override `random` / `getrandbits` / `_randbelow` / `seed` (the algorithm
`Random.__init_subclass__` picks is reproduced) and `SystemRandom`. Output is identical to CPython
3.13 for all of them (tests/36_random.py, tests/51_random_exact.py, and a 300-seed sweep of every
function). A hidden `random._sha512(bytes)` exposes the digest for testing.

## subprocess (src/p7_sock.c `_proc`, host adapter `host_proc_run` in src/p0_os.c, pylib/subprocess.py)

`import subprocess` (POSIX builds only): `run`, `call`, `check_call`, `check_output`, `CompletedProcess`,
`CalledProcessError`, `TimeoutExpired`, `PIPE`, `STDOUT`, `DEVNULL`, and `Popen`: deferred (the child runs to
completion at `communicate()/wait()/poll()`) unless `stdin=PIPE, stdout=PIPE` are both given, then it is live:
the child starts at once in its own process group, `p.stdin.write(...)`, `p.stdout.read1(n, timeout)` /
`p.read_nonblock(timeout)` (None = nothing yet, empty = end of file), `send_signal/terminate/kill`, `poll/wait`.
Natives `_proc.spawn(argv, cwd, merge) -> (pid, in_fd, out_fd, err_fd)`, `read(fd, n, timeout)`, `write`, `close`,
`kill(pid, sig)` (process group), `wait(pid, nohang) -> (done, rc)`; host adapters `host_proc_spawn/read/write/
close/signal/wait` (select on the fds; ENOSYS elsewhere). Test 72. Native part:
`_proc.run(argv, input, timeout, cwd) -> (status, rc, stdout, stderr)` using fork/execvp/pipe/select;
without `-DPY_POSIX` it reports ENOSYS (OSError).

## Optional native hook `_cms` (src/p7_cms.c, `make cms`, `-DPY_CMS`)

Not part of the default build. `make cms` builds `py_cms` with `-DPY_POSIX -DPY_CMS`; `make cms-test` also runs
`tests/cms/*.py`. The module `_cms` is the place for host primitives that exist only on VM/370 CMS:
`_cms.diag58(subcode, data) -> bytes` (DIAGNOSE X'58', 3270 virtual console: data is the command byte, F5 Erase/Write or
F6 Read Modified, followed by the data stream). On a host without the primitive it raises `NotImplementedError`
(`host_diag58` returns 1; under `PY_HOST_CMS` the assembler stub still has to be written, see PORTING.md).
For tests the module has a fake in-memory 3270 host, selected with `_cms.fake()` or `PY_CMS_FAKE=1`: it decodes the
Erase/Write stream into a 24x80 buffer (`fake_screen()`, `fake_cursor()`) and answers Read Modified from replies queued
with `fake_push(aid, row, typed, crow, ccol)`. `workbench/screen_cms3270.py` runs end to end on it
(`PY=c/py_cms sh tests/run_tests.sh`, test `t_cmsnative`). Strict C89 like the rest; `make strict` also checks
the `-DPY_CMS` variants.
